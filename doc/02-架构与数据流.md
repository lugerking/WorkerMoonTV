# 架构与数据流

本文档说明 WorkerMoonTV 的分层架构、配置体系、鉴权模型与主要数据流。

## 1. 分层架构

```
┌───────────────────────────────────────────────┐
│  表现层  src/app/**/page.tsx + src/components  │  客户端组件（React）
├───────────────────────────────────────────────┤
│  中间件  src/middleware.ts                     │  鉴权、签名校验、重定向
├───────────────────────────────────────────────┤
│  接口层  src/app/api/**/route.ts               │  Route Handlers（runtime='nodejs'）
├───────────────────────────────────────────────┤
│  业务/逻辑层  src/lib                          │
│    config.ts  downstream.ts  douban.client.ts  │
│    fetchVideoDetail.ts  utils.ts  version.ts   │
├───────────────────────────────────────────────┤
│  存储层  src/lib/db.ts → IStorage 实现          │
│    d1.db.ts  redis.db.ts  upstash.db.ts        │
│    db.client.ts（localStorage，仅客户端）       │
└───────────────────────────────────────────────┘
```

- **面向接口编程**：存储层统一实现 `IStorage`（`src/lib/types.ts`），业务代码只依赖 `DbManager`（`src/lib/db.ts`）。
- **页面渲染策略**：根布局 `src/app/layout.tsx` 声明 `export const dynamic = 'force-dynamic'`，所有页面**运行时渲染**，以便每次请求读取数据库（D1）中的站点配置。
- **接口运行时**：全部 API 路由声明 `export const runtime = 'nodejs'`（OpenNext 不支持 Next 14 的 edge 路由；Workers 配合 `nodejs_compat` 运行 Node 风格代码）。

## 2. 运行形态（OpenNext + Cloudflare Workers）

- 构建：`opennextjs-cloudflare build` 执行 `next build`，再把产物打包为 `.open-next/worker.js`（服务端）+ `.open-next/assets/`（静态资源）。
- 部署：`wrangler deploy` 上传 Worker 与静态资源；静态资源通过 `wrangler.jsonc` 的 `assets.binding = ASSETS` 提供。
- 请求处理：Worker 入口对每个请求调用 `runWithCloudflareRequestContext(request, env, ctx, ...)`，再由 Next 服务端处理；`env` 中的变量与绑定即运行时配置来源。
- **绑定读取**：OpenNext 只会把**字符串型** env 注入 `process.env`，对象型绑定（如 D1）不会进入 `process.env`。因此 `src/lib/d1.db.ts` 通过全局符号读取绑定：
  ```ts
  const ctx = (globalThis as any)[Symbol.for('__cloudflare-context__')];
  const db = ctx?.env?.DB;          // D1 绑定（用户数据）
  const kv = ctx?.env?.CONFIG_KV;   // KV 绑定（管理员配置）
  ```
- 自定义域：`wrangler.jsonc` 的 `routes` 配置了 `workermoontv.mytvapp.qzz.io`（`custom_domain: true`）。

## 3. 配置体系与优先级

配置来源有三层，`src/lib/config.ts` 的 `getConfig()` 负责合并：

| 来源 | 载体 | 角色 |
| --- | --- | --- |
| `config.json` | 构建期由 `scripts/convert-config.js` 编译进 `src/lib/runtime.ts` | 资源站（`api_site`）与自定义分类（`custom_category`）模板 |
| 环境变量 | `wrangler.jsonc` 的 `vars` / Secret | 站点信息与开关的**默认值** |
| 配置存储 `admin_config` | Workers KV（key `admin_config`，绑定 `CONFIG_KV`） | **最终权威配置** |

**优先级：数据库 > 环境变量/config.json。**

`getConfig()` 逻辑（非 localstorage 模式）：

1. 从 KV 读取 `admin_config`。
2. **若数据库存在配置**：
   - 以数据库为准；仅当字段**缺失**时，才用环境变量/默认值补齐（`SiteName`、`Announcement`、`ImageProxy`、`DoubanProxy`、`DisableYellowFilter`、`AllowRegister`、`SearchDownstreamMaxPage`、`SiteInterfaceCacheTime`）。
   - `config.json` 的 `api_site` 仅用于**补充数据库中不存在的源**（已存在的源保留数据库中的 `name/api/detail`）。
   - `config.json` 的 `custom_category` 同样仅补充数据库中不存在的分类。
   - 依据 `USERNAME` 修正 owner 角色（非 owner 的 owner 角色降级为 user，当前 `USERNAME` 置为 owner）。
3. **若数据库无配置**：调用 `initConfig()`，用环境变量 + `config.json` 构建初始配置并**写回数据库**。

由此，管理后台的修改会持久化到数据库并立即生效；`config.json`/环境变量只在数据库尚无对应值（或字段为空）时作为初始默认。

> 其他辅助函数：`getCacheTime()`（站点接口缓存秒数）、`getAvailableApiSites()`（过滤 `disabled` 后的启用源列表）、`resetConfig()`（重置为 `config.json` + 环境变量的默认值）。

## 4. 鉴权流程

`src/middleware.ts` 对所有匹配路径统一拦截：

1. **白名单跳过**：`/_next`、`/favicon.ico`、`/robots.txt`、`/manifest.json`、`/icons/`、`/logo.png`、`/screenshot.png`。
2. 若未设置 `PASSWORD` → 重定向 `/warning`。
3. 读取 `auth` Cookie：
   - **localstorage 模式**：校验 `authInfo.password === PASSWORD`。
   - **数据库模式**（d1/redis/upstash）：要求存在 `username` + `signature`，并用 `HMAC-SHA256(username, PASSWORD)` 验签。
4. 失败处理 `handleAuthFailure`：`/api*` 返回纯文本 `401 Unauthorized`；页面重定向 `/login?redirect=<原路径>`。

`matcher` 排除：`_next/static`、`_next/image`、`favicon.ico`、`login`、`warning`、`api/login`、`api/register`、`api/logout`、`api/cron`、`api/server-config`。

**双重防线**：除中间件外，敏感接口（`favorites`/`playrecords`/`searchhistory`/`skipconfigs`/`change-password`/`admin/*`）在路由内再用 `getAuthInfoFromCookie(request)` 二次校验；管理接口再叠加 owner/admin 角色判断。

### Cookie 结构（`src/lib/auth.ts`）

| 模式 | Cookie（URL 编码的 JSON） |
| --- | --- |
| localstorage | `{ role, password }` |
| 数据库模式 | `{ role, username, signature, timestamp }`，`signature = HMAC-SHA256(username, PASSWORD)` |

## 5. 主要数据流

### 5.1 聚合搜索

```
搜索页 → GET /api/search?q=关键词
        → getAvailableApiSites() 取启用源
        → 并行 searchFromApi(site, q)（多页抓取，受 SearchDownstreamMaxPage 限制）
        → 扁平化结果；若未关闭黄滤则按 type_name 过滤 yellowWords
        → 返回 { results: SearchResult[] }（带 CDN 缓存头）
```

### 5.2 播放

```
/play 页 → 读取 URL 参数（source/id/title/...）
        → （可选）跨源聚合搜索 + 优选测速（utils.getVideoResolutionFromM3u8，评分=分辨率40%+速度40%+延迟20%）
        → GET /api/detail?source&id → getDetailFromApi() 取 episodes（m3u8 列表）
        → ArtPlayer + HLS.js 播放；过滤 #EXT-X-DISCONTINUITY 去广告
        → 进度通过客户端 db.client 写入播放记录（DB 模式：乐观更新 + 后台同步）
```

### 5.3 豆瓣

```
首页/豆瓣页 → getDoubanList()/getDoubanCategories()（src/lib/douban.client.ts）
           → 依据 NEXT_PUBLIC_DOUBAN_PROXY 决定「服务端 API」或「浏览器代理」
           → GET /api/douban（榜单，tag=top250 走 HTML 正则解析）
              GET /api/douban/categories（rexxar recent_hot）
           → 图片经 getImageProxyUrl()/NEXT_PUBLIC_IMAGE_PROXY 处理
```

### 5.4 管理后台

```
/admin 页（客户端）→ GET /api/admin/config 拉取 AdminConfig
   Tab：站点配置 → POST /api/admin/site
       用户配置 → POST /api/admin/user
       视频源   → POST /api/admin/source
       分类     → POST /api/admin/category
   → 各接口 getConfig() 读取 → 修改 → storage.setAdminConfig() 写回数据库
```

> 由于配置优先级为「数据库优先」，上述修改会持久生效。此前版本中 D1/Upstash 下被禁用的「站点配置、注册开关、分类管理」在本版本均已放开；`config.json` 中定义的源（`from: 'config'`）仍不可删除，但可修改属性、启停与排序。

## 6. 客户端数据同步（`src/lib/db.client.ts`）

- **localstorage 模式**：数据直接写入浏览器 `localStorage`（键如 `playRecords`、`favorites`、`searchHistory`、`skipConfigs`）。
- **数据库模式**：客户端维护 `HybridCacheManager`（localStorage 混合缓存，约 1 小时过期），采用**本地缓存 + 乐观更新 + 后台接口同步**：先更新本地缓存并通知 UI，再调用对应 `/api/*` 接口落库；接口 401 时自动跳转登录页。
- 通过 `subscribeToDataUpdates(event, callback)` 事件订阅实现跨组件刷新（如新增收藏后首页收藏夹即时更新）。
