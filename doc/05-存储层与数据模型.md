# 存储层与数据模型

## 1. 设计目标

WorkerMoonTV 支持 4 种存储后端，通过 `NEXT_PUBLIC_STORAGE_TYPE` 切换：`localstorage`（默认）、`d1`、`redis`、`upstash`。核心设计是**面向接口编程**：所有后端实现统一的 `IStorage` 接口（`src/lib/types.ts`），上层业务只依赖 `DbManager`（`src/lib/db.ts`）暴露的方法。

```
业务代码 (API / 页面)
        │
        ▼
   DbManager (db.ts)  ── generateStorageKey(source, id) => "source+id"
        │
        ▼
   IStorage (types.ts)
        │
   ┌────┼─────────┬──────────────┐
   ▼    ▼         ▼              ▼
  D1  Redis    Upstash     localstorage(客户端 localStorage)
(d1.db.ts)(redis.db.ts)(upstash.db.ts) (db.client.ts)
```

> 本项目生产使用 **D1**。

## 2. 数据模型

### 2.1 PlayRecord（播放记录）

```ts
interface PlayRecord {
  title: string;          // 标题
  source_name: string;    // 源名称
  cover: string;          // 封面
  year: string;           // 年份
  index: number;          // 当前第几集
  total_episodes: number; // 总集数
  play_time: number;      // 播放进度（秒）
  total_time: number;     // 总时长（秒）
  save_time: number;      // 保存时间戳
  search_title: string;   // 搜索时使用的标题
}
```

### 2.2 Favorite（收藏）

```ts
interface Favorite {
  source_name: string;
  total_episodes: number;
  title: string;
  year: string;
  cover: string;
  save_time: number;
  search_title: string;
}
```

### 2.3 SkipConfig（跳过片头片尾）

```ts
interface SkipConfig {
  enable: boolean;      // 是否启用
  intro_time: number;   // 片头时长（秒）
  outro_time: number;   // 片尾时长（秒）
}
```

### 2.4 SearchResult（搜索结果 / 详情）

```ts
interface SearchResult {
  id: string;
  title: string;
  poster: string;
  episodes: string[];   // 播放地址列表（如 m3u8）
  source: string;
  source_name: string;
  class?: string;
  year: string;
  desc?: string;
  type_name?: string;   // 用于色情过滤
  douban_id?: number;
}
```

## 3. IStorage 接口

```ts
interface IStorage {
  // 播放记录
  getPlayRecord(userName, key): Promise<PlayRecord | null>;
  setPlayRecord(userName, key, record): Promise<void>;
  getAllPlayRecords(userName): Promise<{ [key: string]: PlayRecord }>;
  deletePlayRecord(userName, key): Promise<void>;

  // 收藏
  getFavorite(userName, key): Promise<Favorite | null>;
  setFavorite(userName, key, favorite): Promise<void>;
  getAllFavorites(userName): Promise<{ [key: string]: Favorite }>;
  deleteFavorite(userName, key): Promise<void>;

  // 用户
  registerUser(userName, password): Promise<void>;
  verifyUser(userName, password): Promise<boolean>;
  checkUserExist(userName): Promise<boolean>;
  changePassword(userName, newPassword): Promise<void>;
  deleteUser(userName): Promise<void>;  // 级联删除密码/历史/记录/收藏/skip

  // 搜索历史
  getSearchHistory(userName): Promise<string[]>;
  addSearchHistory(userName, keyword): Promise<void>;
  deleteSearchHistory(userName, keyword?): Promise<void>;

  // 用户列表
  getAllUsers(): Promise<string[]>;

  // 管理员配置
  getAdminConfig(): Promise<AdminConfig | null>;
  setAdminConfig(config): Promise<void>;

  // 跳过片头片尾
  getSkipConfig(userName, source, id): Promise<SkipConfig | null>;
  setSkipConfig(userName, source, id, config): Promise<void>;
  deleteSkipConfig(userName, source, id): Promise<void>;
  getAllSkipConfigs(userName): Promise<{ [key: string]: SkipConfig }>;
}
```

> `DbManager` 进一步把 `(userName, source, id)` 组合为内部 `key = ${source}+${id}`（`generateStorageKey`）。

## 4. Cloudflare D1 存储（`src/lib/d1.db.ts`）

关系型存储（**本项目生产使用**）。

### 4.1 绑定获取方式

OpenNext 只把**字符串型**环境变量注入 `process.env`，对象型绑定（D1）不会出现在 `process.env` 中。因此 `D1Storage` 通过 Cloudflare 上下文的全局符号获取绑定：

```ts
function getD1Database(): D1Database {
  try {
    const ctx = (globalThis as any)[Symbol.for('__cloudflare-context__')];
    const db = ctx?.env?.DB;
    if (db) return db as D1Database;
  } catch {
    // 非 Workers 运行时走回退
  }
  return (process.env as any).DB as D1Database;
}
```

> **绑定名必须为 `DB`**（在 `wrangler.jsonc` 的 `d1_databases` 中配置）。

### 4.2 表结构

| 表 | 关键字段 | 约束 |
| --- | --- | --- |
| `users` | `username`(PK), `password`, `created_at` | PK(username) |
| `play_records` | `username, key, title, source_name, cover, year, index_episode, total_episodes, play_time, total_time, save_time, search_title` | `UNIQUE(username, key)` |
| `favorites` | `username, key, title, source_name, cover, year, total_episodes, save_time` | `UNIQUE(username, key)` |
| `search_history` | `username, keyword, created_at` | `UNIQUE(username, keyword)` |
| `skip_configs` | `username, source, id_video, enable, intro_time, outro_time` | `UNIQUE(username, source, id_video)` |

### 4.3 索引

- `idx_play_records_username`、`idx_play_records_username_key`、`idx_play_records_username_save_time`
- `idx_favorites_username`、`idx_favorites_username_key`、`idx_favorites_username_save_time`
- `idx_search_history_username`、`idx_search_history_username_keyword`、`idx_search_history_username_created_at`、`idx_search_history_username_id_created_at`
- `idx_skip_configs_username_source_id`

### 4.4 建表 SQL

首次部署前需在 D1 中执行一次：

```sql
CREATE TABLE IF NOT EXISTS users (
  username TEXT PRIMARY KEY,
  password TEXT NOT NULL,
  created_at INTEGER NOT NULL DEFAULT (strftime('%s', 'now'))
);

CREATE TABLE IF NOT EXISTS play_records (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL,
  key TEXT NOT NULL,
  title TEXT NOT NULL,
  source_name TEXT NOT NULL,
  cover TEXT NOT NULL,
  year TEXT NOT NULL,
  index_episode INTEGER NOT NULL,
  total_episodes INTEGER NOT NULL,
  play_time INTEGER NOT NULL,
  total_time INTEGER NOT NULL,
  save_time INTEGER NOT NULL,
  search_title TEXT,
  UNIQUE(username, key)
);

CREATE TABLE IF NOT EXISTS favorites (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL,
  key TEXT NOT NULL,
  title TEXT NOT NULL,
  source_name TEXT NOT NULL,
  cover TEXT NOT NULL,
  year TEXT NOT NULL,
  total_episodes INTEGER NOT NULL,
  save_time INTEGER NOT NULL,
  UNIQUE(username, key)
);

CREATE TABLE IF NOT EXISTS search_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL,
  keyword TEXT NOT NULL,
  created_at INTEGER NOT NULL DEFAULT (strftime('%s', 'now')),
  UNIQUE(username, keyword)
);

CREATE TABLE IF NOT EXISTS skip_configs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL,
  source TEXT NOT NULL,
  id_video TEXT NOT NULL,
  enable INTEGER NOT NULL DEFAULT 0,
  intro_time INTEGER NOT NULL DEFAULT 0,
  outro_time INTEGER NOT NULL DEFAULT 0,
  UNIQUE(username, source, id_video)
);

CREATE INDEX IF NOT EXISTS idx_play_records_username ON play_records(username);
CREATE INDEX IF NOT EXISTS idx_favorites_username ON favorites(username);
CREATE INDEX IF NOT EXISTS idx_search_history_username ON search_history(username);
CREATE INDEX IF NOT EXISTS idx_play_records_username_key ON play_records(username, key);
CREATE INDEX IF NOT EXISTS idx_play_records_username_save_time ON play_records(username, save_time DESC);
CREATE INDEX IF NOT EXISTS idx_favorites_username_key ON favorites(username, key);
CREATE INDEX IF NOT EXISTS idx_favorites_username_save_time ON favorites(username, save_time DESC);
CREATE INDEX IF NOT EXISTS idx_search_history_username_keyword ON search_history(username, keyword);
CREATE INDEX IF NOT EXISTS idx_search_history_username_created_at ON search_history(username, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_skip_configs_username_source_id ON skip_configs(username, source, id_video);
CREATE INDEX IF NOT EXISTS idx_search_history_username_id_created_at ON search_history(username, id, created_at DESC);
```

执行方式：

```bash
npx wrangler d1 execute moontvdatabase --remote --file=schema.sql
```

### 4.5 说明

- `search_history` 的 `created_at` 精度为秒（`strftime('%s','now')`），同秒多条时依赖 `id` 排序。
- 写操作使用 `INSERT ... ON CONFLICT ... DO UPDATE`（upsert）语义。

## 4.6 Workers KV：管理员配置存储（`src/lib/kv.db.ts`）

管理员配置（`AdminConfig`）**不再存于 D1**，而是存储在**全球分布的 Workers KV** 中，与用户数据存储（D1 / Redis / Upstash）解耦：

- 绑定名：`CONFIG_KV`；key：`admin_config`（存整份 JSON）。
- 读：`getAdminConfig()` → `kv.get('admin_config')` + `JSON.parse`。
- 写：`setAdminConfig()` → `kv.put('admin_config', JSON.stringify(config))`。
- 绑定获取：通过 Cloudflare 上下文全局符号 `Symbol.for('__cloudflare-context__')` 读取（OpenNext 不会把对象型绑定注入 `process.env`）；构建期或非 Workers 环境下返回 null，回退为「环境变量 + `config.json`」的默认配置。
- 适用性：配置属于「读极多、写极少」的数据，KV 的边缘缓存带来低延迟读取；写入频率极低，最终一致性的影响可忽略。

## 5. Redis 存储（`src/lib/redis.db.ts`）

使用 `redis` 官方客户端，通过 `Symbol.for('__MOONTV_REDIS_CLIENT__')` 实现全局单例，带指数退避重连（最大 30s）与 `withRetry`（默认 3 次重试，识别连接类错误后重连）。

### Key 设计

| 数据 | Key 模式 | Redis 类型 |
| --- | --- | --- |
| 播放记录 | `u:{user}:pr:{source}+{id}` | String(JSON) |
| 收藏 | `u:{user}:fav:{source}+{id}` | String(JSON) |
| 用户密码 | `u:{user}:pwd` | String |
| 搜索历史 | `u:{user}:sh` | List（去重 + `lPush` + `lTrim` 保留 20 条） |
| 跳过配置 | `u:{user}:skip:{source}+{id}` | String(JSON) |
| 管理员配置 | `admin:config` | String(JSON) |

- `getAllPlayRecords` / `getAllFavorites` / `getAllSkipConfigs`：先 `keys(pattern)` 再 `mGet` 批量取回。
- `getAllUsers`：`keys('u:*:pwd')` 后用正则提取用户名。
- 搜索历史上限常量 `SEARCH_HISTORY_LIMIT = 20`。
- ⚠️ 密码为**明文存储**（源码注释已提示生产环境应加密）。

## 6. Upstash Redis 存储（`src/lib/upstash.db.ts`）

- 使用 `@upstash/redis`（HTTP 协议，适配 Serverless / Edge）。
- 全局单例键：`Symbol.for('__MOONTV_UPSTASH_REDIS_CLIENT__')`。
- Key 设计与 Redis 完全一致（`u:{user}:pr:{key}`、`u:{user}:fav:{key}`、`u:{user}:pwd`、`u:{user}:sh`、`u:{user}:skip:{source}+{id}`、`admin:config`）。
- 由于 SDK 自动序列化 JSON，`set` 时直接传对象而非字符串。
- 需要 `UPSTASH_URL` + `UPSTASH_TOKEN`。

## 7. 客户端本地存储（`src/lib/db.client.ts`）

- 当存储类型为 `localstorage` 时，`getStorage()` 返回 `null`，由客户端的 `db.client.ts` 接管。
- 数据直接写入浏览器 `localStorage`，键通常为 `playRecords`、`favorites`、`searchHistory`、`skipConfigs` 等。
- 提供 `subscribeToDataUpdates(event, callback)` 事件订阅，用于跨组件刷新（如新增收藏后首页收藏夹即时更新）。
- 对数据库模式，客户端采用 `HybridCacheManager`（约 1 小时过期）+ **乐观更新 + 后台接口同步**策略，保证弱网下的体验。

## 8. 配置持久化

- `AdminConfig` 的持久化统一走 `setAdminConfig(config)`（`src/lib/kv.db.ts`），存储于 **Workers KV** 的 `admin_config` 键（整份 JSON）。
- `getConfig()` 采用**数据库优先**：数据库已有值时以数据库为准，环境变量与 `config.json` 仅作为默认值。详见 [02-架构与数据流](./02-架构与数据流.md#3-配置体系与优先级)。

## 9. 安全说明

- 所有后端实现中的用户密码均为**明文存储**，源码注释已标注「生产环境应加密」，属于已知待改进点。
- Redis 的 `keys(pattern)` 在数据量大时性能较差，属于简化实现。
- 建议为 Redis/Upstash 实例配置访问控制，并按需关闭公网注册（管理后台可切换 `AllowRegister`）。
