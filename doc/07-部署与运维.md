# 部署与运维

## 1. 本地开发

要求 **Node.js 20+**（本项目在 Node 24 下构建通过）与 **npm**。

```bash
npm install

npm run dev     # 先生成 runtime/manifest，再启动 next dev
```

- `npm run dev` 会通过 `next.config.js` 中的 `initOpenNextCloudflareForDev()` 接入 `wrangler.jsonc` 中配置的变量与 D1 / KV 绑定（本地对应 miniflare）。
- 常用脚本（`package.json`）：

| 脚本 | 说明 |
| --- | --- |
| `dev` | `convert-config` → `generate-manifest` → `next dev` |
| `build` | `convert-config` → `generate-manifest` → `next build` |
| `gen:runtime` | `node scripts/convert-config.js` |
| `gen:manifest` | `node scripts/generate-manifest.js` |
| `build:worker` | `convert-config` → `generate-manifest` → `opennextjs-cloudflare build` |
| `preview` | 构建后在本地预览 Worker |
| `deploy` | 构建后部署 |
| `upload` | 构建后上传（不切换流量） |
| `cf-typegen` | 生成 `CloudflareEnv` 类型 |

## 2. 构建期脚本

- **`scripts/convert-config.js`（gen:runtime）**：读取根目录 `config.json`，生成 `src/lib/runtime.ts`，把站点配置编译进产物（Workers 运行时读取）。
- **`scripts/generate-manifest.js`（gen:manifest）**：依据 `SITE_NAME` 生成 `public/manifest.json`。

> 修改 `config.json` 后需重新构建并部署才会生效。

## 3. Cloudflare Workers 部署（OpenNext）

本项目通过 **OpenNext Cloudflare** 适配器打包为 Workers 应用：

- 构建产物：`.open-next/worker.js`（服务端入口）+ `.open-next/assets/`（静态资源）。
- 配置：`open-next.config.ts`（适配器）+ `wrangler.jsonc`（部署）。

### 3.1 前置要求

- Cloudflare 账号与 **API Token**（需 Workers Scripts、D1 等权限）。
- Windows 用户：OpenNext 构建会调用 `bash`，请将 Git 的 `bin` 目录加入 `PATH`；同时把 `node_modules/.bin` 与 Node 安装目录加入 `PATH`，并确保 `PATHEXT` 含 `.CMD`。

### 3.2 环境变量与绑定

**（1）`wrangler.jsonc` 的 `vars`（明文，运行时）**

```jsonc
"vars": {
  "NEXT_PUBLIC_STORAGE_TYPE": "d1",
  "NEXT_PUBLIC_ENABLE_REGISTER": "true",
  "USERNAME": "lugerking"
}
```

**（2）Secret（如 `PASSWORD`）**

```bash
npx wrangler secret put PASSWORD
# 或使用 JSON 文件批量导入：npx wrangler secret bulk secrets.json  （内容形如 {"PASSWORD":"..."}）
```

**（3）D1 绑定（用户数据，绑定名必须为 `DB`）**

```jsonc
"d1_databases": [
  { "binding": "DB", "database_name": "moontvdatabase", "database_id": "<your-db-id>" }
]
```

**（4）KV 绑定（管理员配置，绑定名必须为 `CONFIG_KV`）**

```bash
npx wrangler kv namespace create CONFIG_KV
```

```jsonc
"kv_namespaces": [
  { "binding": "CONFIG_KV", "id": "<your-kv-namespace-id>" }
]
```

> 管理员配置存于该 KV 的 `admin_config` 键（整份 JSON）；为空时会自动用环境变量 + `config.json` 初始化。

> ⚠️ `NEXT_PUBLIC_*` 会在构建时内联进产物，**构建时也必须设置**同名环境变量（见 3.3）。

### 3.3 构建

```bash
# bash
export CLOUDFLARE_API_TOKEN="<token>"
NEXT_PUBLIC_STORAGE_TYPE=d1 NEXT_PUBLIC_ENABLE_REGISTER=true npm run build:worker

# PowerShell
$env:CLOUDFLARE_API_TOKEN="<token>"
$env:NEXT_PUBLIC_STORAGE_TYPE="d1"; $env:NEXT_PUBLIC_ENABLE_REGISTER="true"; npm run build:worker
```

### 3.4 部署

```bash
npx wrangler deploy
# 或（含构建）：npm run deploy
```

自定义域在 `wrangler.jsonc` 的 `routes` 中配置：

```jsonc
"routes": [
  { "pattern": "workermoontv.mytvapp.qzz.io", "custom_domain": true }
]
```

> 绑定了自定义域后 `workers_dev` 默认关闭；若需同时保留 `*.workers.dev`，可显式添加 `"workers_dev": true`。
>
> 注意：`*.workers.dev` 在部分网络环境下会被 DNS 污染而无法访问，此时请使用自定义域。

### 3.5 D1 初始化

首次部署前，使用 [05-存储层与数据模型](./05-存储层与数据模型.md#44-建表-sql) 中的 SQL 在 D1 中建表（管理员配置已迁移到 KV，`admin_config` 不在其中）：

```bash
npx wrangler d1 execute moontvdatabase --remote --file=schema.sql
```

## 4. 定时任务

`/api/cron` 负责刷新所有用户的播放记录与收藏的集数（当总集数变化时更新）：

- Workers 不内置定时调度；需通过**外部触发器**周期性调用，例如：
  - Cloudflare Cron Triggers（另建一个带 `scheduled` 的 Worker 定时 `fetch` 本应用的 `/api/cron`）；
  - 或任意第三方调度服务（如 GitHub Actions、UptimeRobot 等）定时 GET。
- `/api/cron` 在中间件白名单中（免登录），localstorage 模式下直接跳过。

## 5. 关键配置项与调优

| 配置 | 位置 | 说明 |
| --- | --- | --- |
| `cache_time` | `config.json` | 接口缓存秒数（默认 7200），作为 `SiteInterfaceCacheTime` 的默认值 |
| `api_site` | `config.json` | 资源站集合（本项目 20 个），构建期编译进产物 |
| `custom_category` | `config.json` | 自定义分类（当前为空），构建期为默认值 |
| `SiteName` / `Announcement` | 管理后台 / 环境变量 | 站点名称与公告 |
| `SearchDownstreamMaxPage` | 管理后台 / `NEXT_PUBLIC_SEARCH_MAX_PAGE` | 搜索每源最大页数 |
| `SiteInterfaceCacheTime` | 管理后台 / `config.json` | 接口缓存时间 |
| `ImageProxy` / `DoubanProxy` | 管理后台 / `NEXT_PUBLIC_IMAGE_PROXY` 等 | 图片/豆瓣代理前缀 |
| `DisableYellowFilter` | 管理后台 / `NEXT_PUBLIC_DISABLE_YELLOW_FILTER` | 关闭色情过滤 |
| `AllowRegister` | 管理后台 / `NEXT_PUBLIC_ENABLE_REGISTER` | 是否开放注册 |

> **配置优先级：数据库 > 环境变量/config.json**。管理后台的修改会写入数据库并即时生效；`config.json` 与环境变量仅作为初始默认值。因此：
> - 想在界面上长期生效 → 直接在 `/admin` 修改；
> - 想把某项固定为部署默认 → 修改 `config.json`（资源站/分类）或环境变量（站点信息/开关），并**清空/重置**数据库中对应项后重新部署。
>
> 页面为**运行时渲染**（`layout.tsx` 声明 `force-dynamic`），每次请求读取一次 D1 配置。

## 6. 运维与排障

| 现象 | 排查方向 |
| --- | --- |
| `*.workers.dev` 无法访问 | 该域名在部分网络被 DNS 污染，请在 `wrangler.jsonc` 配置自定义域 |
| 数据类接口 500 | 检查 D1 绑定名是否为 `DB`、数据库是否已执行建表 SQL |
| 访问被重定向到 `/login` 或 `/warning` | 未配置 `PASSWORD` Secret |
| 注册提示「当前模式不支持注册」 | `NEXT_PUBLIC_STORAGE_TYPE=localstorage`，需切换为 `d1`/`redis`/`upstash` |
| 注册提示「当前未开放注册」 | 管理后台未开「允许新用户注册」，或 `AllowRegister` 为 false |
| 管理界面改了不生效 | 确认已部署本版本（配置为数据库优先）；检查是否为 `from: 'config'` 的内置源（不可删除） |
| 构建报 `cannot use the edge runtime` | 有 `route.ts` 仍为 `runtime = 'edge'`，需改为 `'nodejs'` |
| Windows 构建报 `spawn bash/npx ENOENT` | 将 Git 的 bash 与 Node 目录加入 `PATH`、`PATHEXT` 含 `.CMD` |
| 分类/站点设置在旧版本中被禁用 | 上游版本在 D1/Upstash 下禁用；本版本已放开 |

## 7. 安全建议

- **必须设置强密码 `PASSWORD`**，否则任何人可访问且会跳转警告页。
- **按需关闭公网注册**（管理后台的「允许新用户注册」，或 `NEXT_PUBLIC_ENABLE_REGISTER=false`）。
- 用户密码为**明文存储**，请勿在不可信环境使用；为 D1/Redis/Upstash 配置访问控制。
- 仅供个人学习使用，请勿公开分享或商用，用户需自行承担法律风险。
