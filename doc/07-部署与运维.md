# 部署与运维

## 1. 本地开发

要求 **Node.js 20+**（本项目在 Node 24 下构建通过）与 **npm**。

```bash
npm install

npm run dev     # 先生成 runtime/manifest，再启动 next dev
```

- `npm run dev` 会通过 `next.config.js` 中的 `initOpenNextCloudflareForDev()` 接入 `wrangler.jsonc` 中配置的变量与 D1 / KV 绑定（本地对应 miniflare）。
- 常用脚本（`package.json`）：

| 脚本 | 说明 |
| --- | --- |
| `dev` | `convert-config` → `generate-manifest` → `next dev` |
| `build` | `convert-config` → `generate-manifest` → `next build` |
| `gen:runtime` | `node scripts/convert-config.js` |
| `gen:manifest` | `node scripts/generate-manifest.js` |
| `build:worker` | `convert-config` → `generate-manifest` → `opennextjs-cloudflare build` |
| `preview` | 构建后在本地预览 Worker |
| `deploy` | 构建后部署 |
| `upload` | 构建后上传（不切换流量） |
| `cf-typegen` | 生成 `CloudflareEnv` 类型 |

## 2. 构建期脚本

- **`scripts/convert-config.js`（gen:runtime）**：读取根目录 `config.json`，生成 `src/lib/runtime.ts`，把站点配置编译进产物（Workers 运行时读取）。
- **`scripts/generate-manifest.js`（gen:manifest）**：依据 `SITE_NAME` 生成 `public/manifest.json`。

> 修改 `config.json` 后需重新构建并部署才会生效。

## 3. Cloudflare Workers 部署（OpenNext）

本项目通过 **OpenNext Cloudflare** 适配器打包为 Workers 应用：

- 构建产物：`.open-next/worker.js`（服务端入口）+ `.open-next/assets/`（静态资源）。
- 配置：`open-next.config.ts`（适配器）+ `wrangler.jsonc`（部署）。

### 3.1 前置要求

- Cloudflare 账号与 **API Token**（需 Workers Scripts、D1 等权限）。
- Windows 用户：OpenNext 构建会调用 `bash`，请将 Git 的 `bin` 目录加入 `PATH`；同时把 `node_modules/.bin` 与 Node 安装目录加入 `PATH`，并确保 `PATHEXT` 含 `.CMD`。

### 3.2 环境变量与绑定

**（1）`wrangler.jsonc` 的 `vars`（明文，运行时）**

```jsonc
"vars": {
  "NEXT_PUBLIC_STORAGE_TYPE": "d1",
  "NEXT_PUBLIC_ENABLE_REGISTER": "true",
  "USERNAME": "lugerking"
}
```

**（2）Secret（如 `PASSWORD`）**

```bash
npx wrangler secret put PASSWORD
# 或使用 JSON 文件批量导入：npx wrangler secret bulk secrets.json  （内容形如 {"PASSWORD":"..."}）
```

**（3）D1 绑定（用户数据，绑定名必须为 `DB`）**

```jsonc
"d1_databases": [
  { "binding": "DB", "database_name": "moontvdatabase", "database_id": "<your-db-id>" }
]
```

**（4）KV 绑定（管理员配置，绑定名必须为 `CONFIG_KV`）**

```bash
npx wrangler kv namespace create CONFIG_KV
```

```jsonc
"kv_namespaces": [
  { "binding": "CONFIG_KV", "id": "<your-kv-namespace-id>" }
]
```

> 管理员配置存于该 KV，按 `SiteConfig` / `SourceConfig` / `CustomCategories` 拆为 3 个 key（`admin_config:site`、`admin_config:sources`、`admin_config:categories`）；用户（含角色/封禁）存于用户数据表，不在 KV。为空时会自动用环境变量 + `config.json` 初始化。

> ⚠️ `NEXT_PUBLIC_*` 会在构建时内联进产物，**构建时也必须设置**同名环境变量（见 3.3）。

### 3.3 构建

```bash
# bash
export CLOUDFLARE_API_TOKEN="<token>"
NEXT_PUBLIC_STORAGE_TYPE=d1 NEXT_PUBLIC_ENABLE_REGISTER=true npm run build:worker

# PowerShell
$env:CLOUDFLARE_API_TOKEN="<token>"
$env:NEXT_PUBLIC_STORAGE_TYPE="d1"; $env:NEXT_PUBLIC_ENABLE_REGISTER="true"; npm run build:worker
```

### 3.4 部署

```bash
npx wrangler deploy
# 或（含构建）：npm run deploy
```

自定义域在 `wrangler.jsonc` 的 `routes` 中配置：

```jsonc
"routes": [
  { "pattern": "workermoontv.mytvapp.qzz.io", "custom_domain": true }
]
```

> 绑定了自定义域后 `workers_dev` 默认关闭；若需同时保留 `*.workers.dev`，可显式添加 `"workers_dev": true`。
>
> 注意：`*.workers.dev` 在部分网络环境下会被 DNS 污染而无法访问，此时请使用自定义域。

### 3.5 D1 初始化

首次部署前，使用 [05-存储层与数据模型](./05-存储层与数据模型.md#44-建表-sql) 中的 SQL 在 D1 中建表（管理员配置已迁移到 KV，`admin_config` 不在其中）：

```bash
npx wrangler d1 execute moontvdatabase --remote --file=schema.sql
```

## 4. 定时任务

`/api/cron` 负责刷新所有用户的播放记录与收藏的集数（当总集数变化时更新）：

- Workers 不内置定时调度；需通过**外部触发器**周期性调用，例如：
  - Cloudflare Cron Triggers（另建一个带 `scheduled` 的 Worker 定时 `fetch` 本应用的 `/api/cron`）；
  - 或任意第三方调度服务（如 GitHub Actions、UptimeRobot 等）定时 GET。
- `/api/cron` 在中间件白名单中（免登录），localstorage 模式下直接跳过。

## 5. 关键配置项与调优

| 配置 | 位置 | 说明 |
| --- | --- | --- |
| `cache_time` | `config.json` | 接口缓存秒数（默认 7200），作为 `SiteInterfaceCacheTime` 的默认值 |
| `api_site` | `config.json` | 资源站集合（本项目 20 个），构建期编译进产物 |
| `custom_category` | `config.json` | 自定义分类（当前为空），构建期为默认值 |
| `SiteName` / `Announcement` | 管理后台 / 环境变量 | 站点名称与公告 |
| `SearchDownstreamMaxPage` | 管理后台 / `NEXT_PUBLIC_SEARCH_MAX_PAGE` | 搜索每源最大页数 |
| `SiteInterfaceCacheTime` | 管理后台 / `config.json` | 接口缓存时间 |
| `ImageProxy` / `DoubanProxy` | 管理后台 / `NEXT_PUBLIC_IMAGE_PROXY` 等 | 图片/豆瓣代理前缀 |
| `DisableYellowFilter` | 管理后台 / `NEXT_PUBLIC_DISABLE_YELLOW_FILTER` | 关闭色情过滤 |
| `AllowRegister` | 管理后台 / `NEXT_PUBLIC_ENABLE_REGISTER` | 是否开放注册 |

> **配置优先级：数据库 > 环境变量/config.json**。管理后台的修改会写入数据库并即时生效；`config.json` 与环境变量仅作为初始默认值。因此：
> - 想在界面上长期生效 → 直接在 `/admin` 修改；
> - 想把某项固定为部署默认 → 修改 `config.json`（资源站/分类）或环境变量（站点信息/开关），并**清空/重置**数据库中对应项后重新部署。
>
> 页面为**运行时渲染**（`layout.tsx` 声明 `force-dynamic`），每次请求读取一次 D1 配置。

## 6. 运维与排障

| 现象 | 排查方向 |
| --- | --- |
| `*.workers.dev` 无法访问 | 该域名在部分网络被 DNS 污染，请在 `wrangler.jsonc` 配置自定义域 |
| 数据类接口 500 | 检查 D1 绑定名是否为 `DB`、数据库是否已执行建表 SQL |
| 访问被重定向到 `/login` 或 `/warning` | 未配置 `PASSWORD` Secret |
| 注册提示「当前模式不支持注册」 | `NEXT_PUBLIC_STORAGE_TYPE=localstorage`，需切换为 `d1`/`redis`/`upstash` |
| 注册提示「当前未开放注册」 | 管理后台未开「允许新用户注册」，或 `AllowRegister` 为 false |
| 管理界面改了不生效 | 确认已部署本版本（配置为数据库优先）；检查是否为 `from: 'config'` 的内置源（不可删除） |
| 构建报 `cannot use the edge runtime` | 有 `route.ts` 仍为 `runtime = 'edge'`，需改为 `'nodejs'` |
| Windows 构建报 `spawn bash/npx ENOENT` | 将 Git 的 bash 与 Node 目录加入 `PATH`、`PATHEXT` 含 `.CMD` |
| 分类/站点设置在旧版本中被禁用 | 上游版本在 D1/Upstash 下禁用；本版本已放开 |

## 7. 安全建议

- **必须设置强密码 `PASSWORD`**，否则任何人可访问且会跳转警告页。
- **按需关闭公网注册**（管理后台的「允许新用户注册」，或 `NEXT_PUBLIC_ENABLE_REGISTER=false`）。
- 用户密码为**明文存储**，请勿在不可信环境使用；为 D1/Redis/Upstash 配置访问控制。
- 仅供个人学习使用，请勿公开分享或商用，用户需自行承担法律风险。

## 9. 私有服务器部署（Linux 自托管）

以 Ubuntu + systemd + Nginx + Redis 为例（本仓库已按此方式在线上运行）。

### 9.1 架构

```
浏览器 → Nginx(80) → Node standalone(127.0.0.1:3000, systemd 服务 moontv)
                        ├── Redis        用户/配置/播放记录/豆瓣缓存（NEXT_PUBLIC_STORAGE_TYPE=redis）
                        └── /opt/moontv/cache    图片/视频本地磁盘缓存
moontv-cron.timer（每日 04:30）→ GET /api/cron → 豆瓣缓存预刷新 + 磁盘缓存按上限清理
```

### 9.2 服务器准备

```bash
# Node 20+（示例安装到 /usr/local/node）、Redis、Nginx
apt-get install -y nginx redis-server
# Redis 设置访问密码（/etc/redis/redis.conf: requirepass <随机密码>）
# 专用运行账号与目录
useradd -r -s /usr/sbin/nologin moontv
mkdir -p /opt/moontv/cache && chown -R moontv:moontv /opt/moontv
```

### 9.3 环境变量

`/etc/moontv.env`（systemd `EnvironmentFile`，权限 600）：

```ini
PASSWORD=<站点登录密码>
USERNAME=<站长账号名>
REDIS_URL=redis://:<redis密码>@127.0.0.1:6379
NEXT_PUBLIC_STORAGE_TYPE=redis
NEXT_PUBLIC_ENABLE_REGISTER=true        # 构建期变量，需在构建时注入；此处仅兜底
NEXT_PUBLIC_IMAGE_PROXY=/api/image-proxy?url=   # 构建期兜底：Redis 管理配置丢失时图片代理仍生效
```

> 注意：`NEXT_PUBLIC_*` 变量在**构建期**注入前端产物，服务器 env 只对服务端生效；管理后台修改即时生效且优先级高于环境变量。

**Redis 数据可靠性**（重要）：播放记录、收藏、管理配置均存 Redis。Redis 重启若无持久化会**丢掉管理配置和历史数据**（曾导致图片代理配置丢失、海报恢复直连被拦）。务必开启持久化：

```bash
redis-cli -a <密码> config set appendonly yes   # 开启 AOF（每秒 fsync，最多丢 1 秒写入）
redis-cli -a <密码> config rewrite              # 写入 redis.conf 永久生效
```

### 9.4 构建与打包（本机执行）

```bash
npm install --legacy-peer-deps
NEXT_PUBLIC_STORAGE_TYPE=redis NEXT_PUBLIC_ENABLE_REGISTER=true npm run build
cp -r .next/static .next/standalone/.next/static
cp -r public .next/standalone/public
tar -C .next/standalone -czf moontv.tar.gz .
scp moontv.tar.gz root@<服务器>:/tmp/
```

### 9.5 systemd 服务

`/etc/systemd/system/moontv.service`：

```ini
[Unit]
Description=MoonTV (Next.js standalone)
After=network.target redis-server.service

[Service]
User=moontv
WorkingDirectory=/opt/moontv
EnvironmentFile=/etc/moontv.env
ExecStart=/usr/local/node/bin/node server.js
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

每日定时任务（豆瓣缓存预刷新 + 磁盘缓存清理）——`/etc/systemd/system/moontv-cron.service`：

```ini
[Unit]
Description=MoonTV daily cron

[Service]
Type=oneshot
ExecStart=/usr/bin/curl -fsS http://127.0.0.1:3000/api/cron
```

`/etc/systemd/system/moontv-cron.timer`：

```ini
[Unit]
Description=Run moontv cron daily

[Timer]
OnCalendar=*-*-* 04:30:00
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
systemctl daemon-reload
systemctl enable --now moontv moontv-cron.timer
```

### 9.7 升级流程（保留缓存）

```bash
systemctl stop moontv
find /opt/moontv -mindepth 1 -maxdepth 1 ! -name cache -exec rm -rf {} +
tar -xzf /tmp/moontv.tar.gz -C /opt/moontv
chown -R moontv:moontv /opt/moontv
systemctl start moontv
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/login   # 期望 200
```

> 关键点：`! -name cache` 保证升级不清空图片/视频磁盘缓存。

### 9.8 自托管增强功能说明

| 功能 | 原理 | 验证方式 |
| --- | --- | --- |
| 图片缓存 | 海报经 `/api/image-proxy` 同源代理，服务端带 Referer 回源豆瓣并落盘 `/opt/moontv/cache/image/`（解决浏览器直连 `doubanio.com` 被跨域拦截） | 响应头 `X-Image-Cache: MISS → HIT`；`/api/admin/image-cache` 返回 `available:true` |
| 视频缓存 | m3u8 播放列表服务端广告过滤改写（`lib/m3u8-filter.ts` 四算法）、分片落盘 `/opt/moontv/cache/video/`，容量上限默认 5GB（管理后台可调）；带 `ep` 的列表响应 `no-store`，顶级列表与分片长期缓存 | 响应头 `X-Video-Cache: MISS → HIT`；`/api/admin/video-cache` |
| 去广告 | 服务端 `/api/video-cache`（原生 HLS 路径）与客户端 hls.js loader 共用 `lib/m3u8-filter.ts`；客户端代理 URL 带 `v=<算法版本>` 破缓存参数 | `curl '/api/video-cache?u=<b64url>&ep=<sha256>'` 段数少于原列表且无广告段 |
| 本地磁盘缓存层 | `src/lib/r2-local.ts` 实现 R2 `get/put/head/delete/list` 兼容接口，无 R2 绑定时自动降级；cron 按访问频率淘汰超限文件 | `ls /opt/moontv/cache/*` 可见缓存文件 |
| 豆瓣推荐缓存 | `src/lib/douban.server.ts`：Redis 缓存 24h → 进程内存降级 → 回源豆瓣；cron 每日强制预刷新首页 3 个区块（热门电影/剧集/综艺） | 响应头 `X-Douban-Cache: fresh → redis`；`redis-cli --scan --pattern 'douban:cat:*'` 可见 key 且 TTL≈86400 |
| PWA 修复 | `/sw.js` 加入中间件白名单 | `curl -I http://<host>/sw.js` 返回 200（未登录也应 200） |

> **过滤算法升级注意**：带 `ep` 参数的播放列表响应为 `Cache-Control: no-store`，算法升级即时生效，无需清缓存；仅管理后台「整集缓存」落盘的顶级列表是旧算法结果，必要时用 `/api/admin/video-cache` 的 `delete`/`evict` 清理。客户端代理 URL 带 `v=<算法版本>` 参数（`play/page.tsx` 的 `buildNativeProxyUrl()`），用于绕过旧版本曾以 `max-age=31536000` 下发、被浏览器长期缓存的列表；**每次调整过滤算法后应递增该版本号**（当前为 `v=2`，曾导致部署新算法后广告仍出现的线上事故）。

### 9.9 HTTPS 配置（Let's Encrypt，IP 直连）

线上域名 `lhq666.cc.cd` 已启用 HTTPS，访客**直连**源站 443（不经 CDN 代理）。

**架构与约束（实测结论）**

| 事项 | 结论 |
| --- | --- |
| 阿里云 ICP 拦截 | 未备案域名：80 端口返回「域名暂时无法访问」拦截页（HTTP-01 验证不可行）；443 TLS 直连实测放行 |
| HTTP-01 / TLS-ALPN-01 | HTTP-01 被拦截；**TLS-ALPN-01 签发成功**（acme.sh `--alpn`，签发瞬间短暂占用 443） |
| Cloudflare 橙云代理 | 免费版无中国节点，CF→源站绕国际线路，实测 9~24s/请求甚至超时，**弃用**；域名仅作 DNS 托管（灰云） |
| 证书 | Let's Encrypt（ECC），90 天，acme.sh cron 自动续期（每天 4 个时点检查，TLS-ALPN 方式，pre/post hook 自动停启 nginx） |

**相关文件**

```
/etc/nginx/ssl/lhq666.crt|key        # acme.sh install-cert 目标（reload hook 已挂）
/etc/nginx/conf.d/moontv-tls.conf    # 443/8443 TLS server 块（域名 SNI）
/etc/nginx/conf.d/moontv-worker.conf # 8080 server（曾用于 CF Worker 回源，现已弃用可删）
/root/.acme.sh/                      # acme.sh，续期 cron: 50 5,11,17,23 * * *
```

**手动续期/重新签发**

```bash
/root/.acme.sh/acme.sh --renew -d lhq666.cc.cd --ecc --force
# 或重新签发：--issue -d lhq666.cc.cd --alpn --server letsencrypt \
#   --pre-hook "systemctl stop nginx" --post-hook "systemctl start nginx"
```

> 注意：HTTP 明文访问域名会命中阿里云拦截页（80 被拦），用户需直接使用 `https://`；现代浏览器输入裸域名会自动尝试 HTTPS。Cloudflare 面板保持 **DNS only（灰云）**，若误开橙云会导致明显变慢。

### 9.10 自托管排障

| 现象 | 排查方向 |
| --- | --- |
| 服务起不来 | `journalctl -u moontv -n 50`；检查 `/etc/moontv.env` 权限与 REDIS_URL |
| 页面能开但数据 500 | Redis 未授权/密码错：`redis-cli -a <密码> ping` |
| 海报不显示 | 管理后台确认图片代理已开启（`ImageProxy=/api/image-proxy?url=`）；`curl -I` 看响应头 |
| 首页推荐区为空 | 豆瓣 rexxar 上游临时不可用；看 `journalctl -u moontv` 中 `[douban-cache]` 日志；手动 `curl /api/cron` 触发预刷新 |
| 磁盘缓存未生效 | 确认目录可写：`sudo -u moontv test -w /opt/moontv/cache && echo ok`；`DISABLE_LOCAL_CACHE` 是否误设 |
| 海报直连 doubanio 被拦（部分图挂） | Redis 管理配置丢失（重启未持久化）：`/admin` 重新保存站点设置；确认构建时注入了 `NEXT_PUBLIC_IMAGE_PROXY` 兜底 |
